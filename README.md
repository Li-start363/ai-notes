## 1. 上下文纪律
**问题**:上下文是 AI 的工作记忆,也是最容易被垃圾吃掉的地方。实测过一次:读结果文件把上下文吃到 519%,后面全在噪声里挣扎。

- **上下文进度条当仪表盘看**;一次工具调用返回超过几千字符原始内容,就该换成"子 agent 去读、我只要结论"。
- **`clear` 当作一个阶段的句号**:该阶段的产物全部落盘、结论全部写入持久记忆/文档之后,才清。清早了=丢工作,清晚了=拖着垃圾跑。
- **日志先 grep/head/tail 定位,读文件用 offset/limit**——别把 3MB 的日志当文章读。

## 2. 双保险:hook + 记忆
**原则**:约束能落实,比反复踩同一个坑便宜得多。

- **方案先行**:非平凡任务动手前先出内部方案(拆解步骤 / 要用哪些 Skill 与记忆 / 这类任务踩过的坑 / 收尾自检清单)。轻任务不生成,长任务必须。
- **hook 管硬约束**(禁止自动关机、外发先问、禁词拦截),**记忆管经验**(上次怎么错的、口径是什么)。两层都要有:hook 拦"不许做",记忆提醒"该做什么"。
- **⚠️ hook 失效是静默的**——脚本被删/语法错/超时,框架不报错,只是不再提醒。换机器、改配置、升级 CLI 后,必须用一条测试 prompt 验证它真的弹了。

## 3. 自检循环
**问题**:AI 会"想当然"——回答说做完了,其实根本没做,或者只是推测。

- **不信 `*_DONE`/`全部完成` 这类标记,只信产物**:文件存在、非零字节、字段齐全、数字对得上判据。踩过的实锤:脚本三步全挂,照样打印 `ALL_DONE`。
- **落盘三要素**:说"已写在 X",必须给出机器 + 绝对路径 + 字节数。"我准备好了"不算落盘。
- **自问自答要含证伪轮**:多轮复盘里至少一轮"假定结论是错的,去找反证";判据要匹配结论的独有串(踩过:`grep "构建成立"` 命中的是字段名,永真)。
- **传文件必 md5 双侧对照**;说"全部/没有/残留 0"之前先 grep,并写明搜索范围。

## 4. 子 agent 分工
**模式**:主 agent 当大脑(定方案、判结果、落盘),子 agent 当手脚(读大文件、巡检、跑命令)。

- 只读任务随便并行;**写任务并行会互踩**——要么分派不相交的目录,要么串行。
- **子 agent 的结论不是证据**:它适合搜/读/跑,不适合定口径;回收的"已完成"要按三要素抽查。
- 动脑的活派"全能力"的子 agent(继承上下文的 fork),机械的活派轻量的;别为省 prompt 把判断活降级。

## 5. 知识库与防编造
- **知识库是长任务的开端,也是 AI 不编造的前提**:先建/先核一手材料,再让它工作。
- **引用必须真实存在、逐条可核**:每条文献先取到原文再写,核不到就不写;二手来源只能当线索。幻觉引用是学术事故,不是笔误。
- **外部状态都有 TTL**:API 可用性、软件版本、网站结构、期刊体例都会漂。依赖外部状态的结论标注取数日期,复用前重验。

## 6. 卡点要问人,别硬磨
登录墙、反爬、机构认证、缺资源——打不通但属于最优路径时,**停下来问人**(开梯子、登录、给凭据),别绕次优路,也别反复撞壁浪费 token。同样,**不可逆/外发/花钱的动作先确认**;可逆的内部动作自主做。

## 7. 未覆盖面机制
收尾时永远说清:**扫了哪几面、没扫哪几面**。禁止"没了/全部完成"这类全称判断——全称判断几乎总是错的,而且会传染给下一轮。诚实的边界声明比虚胖的"完成"值钱。

## 8. 七条工程加固
1. **Skill/提示词体积失控是下一个坑**:速查表 + 指针(<5KB),历史拆出去按需读。
2. **证伪轮规则**:见 §3;10 轮没有 1 轮找反证 = 复读。
3. **写任务不并行**:见 §4。
4. **外部状态标注日期**:见 §5。
5. **hook 静默失效要自证**:见 §2。
6. **自主度分级**:可逆内部动作自主;隐私/外发/花钱先确认。
7. **改配置/批量删之前留带日期的快照**:改坏可回滚。

## 9. 决策/执行分离 —— Token 经济学
**观察**:token 的浪费有两种——花在不需要思考的地方(执行被当成决策),和花在没想清楚的地方(决策被当成执行)。前者烧钱,后者烧钱**还**放大错误:一个坏决策会让下游全部返工。

**四问分类法**——每一步开工前问四个问题,"是"越多越值得花贵算力决策:

| 问 | 决策步(强模型、多候选、判官复核) | 执行步(便宜模型、单轮、机检门禁) |
|---|---|---|
| 错误代价高 / 不可逆? | 选型、定判据、写主张 | 填内容、改格式、批量改写 |
| 答案空间开放? | 无标准答案,要权衡 | 有规格卡,照单产出 |
| 结果不可机检? | 表述是否过头、论证是否成立 | 词数/引用/测试可机器验证 |
| 输出约束下游所有步? | **大纲、判据、清单 = 最值钱** | 只消耗前文,不产生约束 |

**大纲先行模式**(写作实例):①强模型出带建议的大纲(决策物化)→ ②便宜模型按大纲逐节填充(已知工作)→ ③机器门禁(词数/引用/红线)→ ④强模型审读改判。把"想"的算力留在 ①④,把"写"的算力降到 ②。

**实证注记**:我们在受控实验里看到的收益分布支持这个直觉——提示词合同(一种决策脚手架)的增益主要出现在决策型任务(研究构想类 +17.7 分),而在照章执行型任务上不稳定;反例也有:把长前言塞进执行预算里,直接挤掉交付本体(输出被截断)。**算力放错位置不只是浪费,是伤害。**

**失败信号**:执行步开始"自由发挥"(超出规格)= 退回决策步补规格;决策步输出里塞满执行细节 = 浪费,砍。

## 10. 把决策机制做成产品 · 双层分发
把上面这套"人立规则、机器执行"的分工,做成用户无感的一站式工具:

- **双层 API**:用户配置自己的**决策层**与**执行层** key(BYOK,工具不持 key、不转售);
- **任务识别层**:请求进来先识别任务类型,标签亮起,按该任务的"该怎么决策、怎么执行"自动分流;
- **优化入口**:用户告知主要工作方向,工具征得同意后花少量 token 自动做小规模对照实验,优化路由配置并汇报;
- **计费器**:决策层/执行层 token 分账,消耗看得见;
- **诚实定位**:不宣称"自动择优"——我们实测过开放择优在真实任务分布上会被证伪;工具只做**分工与排雷**(已知失效的模型带出处排除),择优留给用户和数据。

> 这套心得的实证工具见 [contract-core](https://github.com/Li-start363/contract-core)——让便宜模型先想再写的"合同"机制,含实测数据与诚实失效地图。
