***<u>关于ai的几点使用心得-lhy-11.10</u>***     ——claude cli

1，上下文的问题，首先设置上下文进度条，不要等压缩节省成本等同时不会降智，clear命令当作一个阶段的结束，必须这个阶段的东西都落实好。

2，hook+记忆都双保险，任何任务都先生成方案（同时方案中包含记忆和skills的提示），三档任务决定方案成熟度，轻任务（日常对话）不生成，涉及工作，长任务（设计步骤脚本规划每一步，同时每一步都有对应的记忆和skills约束，不踩以前的坑）---保证约束能落实，比反复踩之前的坑更省token

3，如果ai不够强，关键任务总结要多轮自问自答，自我优化，token换智能水平

4，mcp必要的就好不要冗余，包括记忆和skills，任何优化都有边际效应，而且如果记忆冲突会更混乱

5，建立好一个知识库是完成一个长任务的开端，也是ai不编造的前提

6，ai总会想当然一些问题，加入自检机制，相当于一轮的自问自答，阻止ai不经查证的回答（回答成功，保存，但可能只是想当然其实根本没有做）

7，ai会踩坑，把走过的错路让ai自动学习加入此类问题的skills，不混入上下文

8，子agent可以多路并行加快效率，也可以完成读文件这类事情，让主agent当大脑，把任务分配出去给子agent，防止上下文频繁爆满

9，对于必须人参与的事情，ai要学会解决不了询问也没有此类型的资源，比如网络受限资源，需要即问，不要自己反复撞壁

10，加入未覆盖面机制，诚实反馈没有做的工作

<u>***ai补充-ai-11.10***</u>

1，**Skill 体量失控是你的下一个坑**

建议:SKILL.md 只留「现行值速查 +指针」(<5KB),历史段、长清单、对照表拆到同目录 history.md / tables.md,按需Read。

2， **自问自答必须含一轮"证伪轮",否则 10 轮是复读**

规则:10 轮里至少 1 轮**假定结论是错的去找反证**;判据匹配 verdict独有串,不匹配属性名。

3，**子 agent 的结论不是证据**

子 agent 适合搜/读/跑,不适合定口径。它回的"已完成/全部"必须按落盘三要素抽查。另:只读任务可随便并行,**写任务并行会互踩**——要么分派不相交目录,要么串行。

4，**外部状态都有 TTL**

API 可用性、云端在线、软件版本、网站 DOM、期刊体例都会漂。凡结论依赖外部状态,标注取数日期,复用前重验

5，**Hook 会静默失效——它不报错,只是不再提醒**

 换机器、改 settings、升级 CLI 后,用一条测试 prompt 验证它真的弹了

6，**不可逆动作做自主度分级**

可逆的内部动作自主做，设计隐私，重要的工作要先确定

7，**改配置/批量删之前留快照**

凡动 hook/settings/记忆/批量删,先 cp  -r 留一份带日期的快照。
